# Fundamental frequency

AudioSpylt has two f0 estimators. `pyin(audio, sr, fmin=..., fmax=...)` tracks
f0 over time, one value per analysis frame. `harmonic_f0(snapshot, fmin=...,
fmax=...)` finds the single f0 that best explains the partials of one snapshot
table as harmonics. `pyin` needs `audiospylt[librosa]`; `harmonic_f0` needs only
the core install.

```python
import audiospylt as asp

x, sr = asp.load_audio("samples/cello_arco_d_sul_c_01.wav", mono=True)
contour = asp.pyin(x, sr, fmin=65.41, fmax=2093.0)  # C2 to C7
tracks = asp.f0_to_tracks(contour)
fig = asp.viz.plot_spectrogram(asp.spectrogram(x, sr), overlay=tracks)

segment = asp.trim(x, sr, 1.5, 2.5)
peaks = asp.find_peaks(asp.spectrum(segment, sr), min_db=None, prominence_db=10, rel_db=-40)
result = asp.harmonic_f0(peaks, fmin=35, fmax=150)
print(f"{result.f0:.2f} Hz, {result.rms_cents:.2f} cents RMS")  # 74.40 Hz, 17.79 cents RMS
```

## f0 over time: `pyin`

`pyin` runs librosa's pYIN and then refines each voiced frame on its harmonics.
`fmin` and `fmax` are required. A range that does not fit the instrument fails
silently (octave errors, or frames that read unvoiced), so there is no default.
Frames are centred like `spectrogram()` with the same `frame_length` (2048) and
`hop` (512): `contour.times` equals `spectrogram(x, sr).times`, so the contour
lines up with spectrogram frames. A frame of 2048 samples holds two periods of
43 Hz at 44.1 kHz. librosa warns when fewer than two periods of `fmin` fit, and
such frames tend to read unvoiced.

The result is an `F0Contour` with one value per frame:

| field | meaning |
| --- | --- |
| `times` | frame centres in seconds, `k * hop / sr` |
| `f0` | f0 in Hz; NaN where unvoiced |
| `voiced`, `voiced_prob` | pYIN's voicing decision and probability |
| `f0_pyin` | pYIN's own value, NaN where unvoiced |
| `refined` | True where `f0` comes from the harmonic refit |
| `amp` | peak amplitude of the fundamental (as in `find_peaks`); NaN where unvoiced, 0 where no spectral peak lies within 50 cents of `f0` |

### Why the refit

pYIN reports f0 on a grid of 0.1 semitone (10 cents), and at low f0 it reads
high. A steady sine yields one to three distinct values, with these errors at
frame 2048 and 44.1 kHz:

| sine | pYIN (median) | after the refit (largest error) |
| --- | --- | --- |
| 73.8 Hz | +21.1 cents | 1.2 cents |
| 110 Hz | +10.1 cents | not measured |
| 223.3 Hz | +4.3 cents | 0.02 cents |
| 445 Hz | +0.5 cents | not measured |

With frame 4096 the 73.8 Hz error is +11 cents. librosa's finer grid
(`resolution=0.01`) takes about 30 times as long and still reads the 73.8 Hz
sine +18 cents high, and on a 15-second soprano recording it marked every frame
unvoiced.

The refit takes each voiced frame's spectrum (Hann window, 4× zero-padding, the
same frame as the spectrogram) and its QIFFT peaks within 60 dB of the frame's
strongest peak, below 5 kHz (or 2·`fmax`, at most `sr/2`). Harmonic *k* takes the
strongest peak within 50 cents of *k*·f0. The fitted f0 minimises the
amplitude-weighted squared log residuals of the matched peaks. The first fit
uses harmonics 1–8 around pYIN's value, the second uses all harmonics around the
first fit, with windows also limited to ±f0/4 Hz so that neighbouring harmonics
never share a window. Measured on synthetic tones:

| signal | pYIN | refit |
| --- | --- | --- |
| sawtooth 73.8 Hz, 29 harmonics | +1.07 cents (every frame) | 0.31 cents (largest) |
| harmonics 2–6 of 110 Hz (no fundamental) | not measured | 0.13 cents (largest); `amp` is 0 |
| sawtooth 220 Hz, ±50 cents vibrato at 5.5 Hz | 8.8 cents (95th percentile) | 1.6 cents (95th percentile) |

On the cello sample (D2, 1–7 s) pYIN gives two distinct values and the refit a
median of 74.31 Hz with a spread of 4.0 cents. There is no ground truth for that
recording. `refine=False` keeps pYIN's values; `amp` is still measured.

Limits:

- The refit follows pYIN's octave and cannot correct an octave error.
- A frame without a peak near any harmonic keeps pYIN's value (`refined` is
  False there).
- The refit adds about 1 s per 8.5 s of 44.1 kHz audio. The first `pyin` call in
  a Python process also compiles librosa's decoder, which takes several seconds.

### As a tracks table

`f0_to_tracks(contour)` turns the voiced frames into a `tracks` table (see
[table-format.md](table-format.md)): one row per voiced frame, `freq` = f0,
`amp` = the fundamental's amplitude, and a new `track_id` after every unvoiced
gap. The extra columns `voiced_prob` and `refined` and `attrs["meta"]` (method
and analysis settings) are kept by `write_table`. Frames with a missing
fundamental have `amp` 0, so they plot and resynthesise as silent even though
their pitch is known.

To hear a contour, `synthesize(tracks_to_events(tracks), sr, fade=0.005)` plays
each track as one phase-continuous sine (see
[synthesis.md](synthesis.md#tracks)). On a 220 Hz sine with a 5 Hz, ±30-cent
vibrato, `pyin` reads the resynthesis within 1.2 cents of the original, and the
amplitude envelopes agree within 0.04 dB.

## One snapshot: `harmonic_f0`

`harmonic_f0` replaces the 0.6 `search_f0`. It minimises the same quantity, the
weighted RMS of `1200·log2(freq / (n·f0))` with `n = round(freq / f0)` (at least
1). The weights are amplitudes by default (`weight="amp"`); `weight="equal"`
gives the 0.6 default. Instead of a 0.001 Hz grid it finds each local optimum
exactly: for a fixed set of harmonic numbers the best f0 has a closed form, and
starting points come from a grid fine enough that no partial skips a harmonic
number. On the cello snapshot above it matches the 0.6 grid result to 0.0003 Hz.
Every row takes part, so filter the snapshot first (`rel_db`, `prominence_db`,
`fmin` in `find_peaks`). Rows at 0 Hz are skipped (harmonic 0, NaN cents).

A subharmonic f0/2 explains every partial at least as well as f0, so the lowest
error usually lies an octave or more too low. On the cello snapshot the true
74.40 Hz scores 17.79 cents and 37.20 Hz scores 17.23 cents; on its 30 strongest
peaks the two tie exactly, and the next octave up (148 Hz) scores 190–270 cents.
`harmonic_f0` therefore returns the highest candidate whose error is within
`tol_cents` (default 3) of the lowest. `tol_cents=0` returns the lowest, as
`search_f0` did. All candidates are in `candidate_f0` and `candidate_rms`;
`harmonics` and `cents` give each row's harmonic number and residual at the
chosen f0.
